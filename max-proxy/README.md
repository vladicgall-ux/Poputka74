# Прокси для MAX (РФ-регион)

Лёгкий обратный прокси без БД и бизнес-логики. Не хранит и не обрабатывает
никаких данных — просто форвардит каждый входящий запрос (любой метод, путь,
заголовки, тело — включая multipart-загрузку фото) на основной сервер
"Поехали 74" в Нидерландах и пересылает ответ обратно as-is.

## Зачем

MAX Mini App у части пользователей не открывается без VPN, если сервер стоит
за границей (мобильные операторы в РФ замедляют/обрывают связь с зарубежными
адресами). Этот прокси разворачивается отдельным ботом/проектом на
**РФ-регионе bothost** — у него российский IP, и запросы от MAX-клиентов до
него доходят напрямую, без VPN. Сам прокси только пересылает трафик дальше
на существующий сервер (Нидерланды) — там всё как было: одна БД, один Express,
один Telegram-бот на long polling.

Telegram-трафик через прокси не идёт (Telegram работает и напрямую) — только
`WEBAPP_URL` в конфиге MAX (business.max.ru) указывает на домен этого прокси.

## Деплой на bothost

Тот же процесс, что описан в README корня репозитория для основного проекта
(bothost собирает `dist/index.js` без отдельного шага сборки TypeScript, так
что `dist/` в этой папке тоже должен быть закоммичен и обновлён перед пушем):

1. Создайте новый проект/бота на bothost, **регион — РФ**, Node.js, репозиторий
   этот же, но нужно указать эту папку (`max-proxy/`) как корень проекта — если
   bothost не даёт выбрать подпапку монорепозитория, вынесите содержимое этой
   папки в отдельный git-репозиторий (структура файлов не изменится).
2. Включите "Использовать домен" (порт 3000).
3. Переменные окружения:
   - `UPSTREAM_URL` — публичный адрес основного сервера в Нидерландах
     (например, `https://bot1234.bothost.tech`), **обязательно с `https://`**.
4. Запустите — прокси должен подняться. Проверьте `https://<домен-прокси>/_proxy/health`
   в браузере: должен ответить `{"ok":true,"upstream":"..."}` — это подтверждает,
   что жив сам прокси, независимо от того, отвечает ли основной сервер.
5. Пропишите домен прокси в `WEBAPP_URL` конфига MAX Mini App (business.max.ru).
   `WEBAPP_URL` основного сервера (для Telegram) не трогайте — он остаётся как есть.

## Локальный запуск

```bash
cp .env.example .env   # заполните UPSTREAM_URL
npm install
npm run dev
```
